# Next.js Capstone — submission checklist

This is the full ADDIS EATS App Router capstone carried forward through Day 10. Before submitting, fill in the evidence below from your own deployed build.

| Evidence | Required record | Current status |
|---|---|---|
| Routes/rendering | Exact route table from `npm run build`, reconciled with `STRATEGY.md` | Not run here |
| Component boundaries | Component-by-component client/server rationale in `BOUNDARY.md` | Included; review after changes |
| Authentication | Protected-route layers and write ownership in `AUTH.md` | Demo auth; replace for production |
| Client data | Query keys and refresh policies in `DATA.md` | Included; orders still in-memory |
| Performance | Before/after Lighthouse report in `PERF.md` | Measurements TODO |
| SEO/metadata | HTML source, sitemap, robots, Open Graph and JSON-LD checks in `SEO.md` | Checks documented; live debugger not run |

The submission is not deployment-complete until the demo accounts are replaced, orders use persistent storage, production checks pass, the real GitHub repository is pushed, and the real deployed URL is recorded in `README.md`.
